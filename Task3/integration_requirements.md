# Cписок требований для внешних интеграций

- Поддержка mTLS (сертификаты X.509) для канальной аутентификации.
- Поддержка OAuth2 client_credentials + JWT (signed) для авторизации API-вызовов.
- TLS 1.3 (или 1.2 с современными наборами шифров).
- Подпись payload (JWS) или HMAC + timestamp + nonce для webhooks.
- Шифрование чувствительных полей JWE / field-level encryption; ключи управляются только через KMS/HSM.
- Контракт API в OpenAPI; schema validation на Integration Gateway; versioning и backward compatibility требования.
- Политика хранения ПДн/биометрии: где хранится, как долго, кто имеет доступ; требование — минимум хранение у партнёра, либо хранение только зашифрованных шаблонов.
- Регулярные аудиты безопасности и возможность проведения аудитов со стороны заказчика.
- Наличие процедур incident response и контингентного плана (телеметрия, контактные лица, эскалации).
- Все шаблоны биометрии должны быть cancellable / revocable или подлежат обновлению при компрометации ключей.
- Минимизация данных: передавайте только то, что нужно для решения (не отправлять видео целиком, если достаточно шаблона).
- Логирование доступа к биометрии и ПДн + журнал действий (кто, когда, зачем).
- «Сегментирование» интеграций: каждая внешняя интеграция — через Integration Gateway с собственными наборами правил/сертификатами.
- Тонкая ролевая модель (RBAC) и, при необходимости, атрибутная (ABAC) — для контроля доступа к функциям «открыть дверь», «получить запись биометрии» и т.д
- Rate limiting, throttling и circuit breakers для защиты от флуд-атак и проблем у партнёра.
- DLP (Data Loss Prevention) на границе и при экспорте данных
